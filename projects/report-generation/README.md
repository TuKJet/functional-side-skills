# 报告生成（设计中）

本分项尚未形成可安装的 Skill。这里故意不创建 `SKILL.md`：在触发条件、依赖和交付形态未确定前，
发布 Skill 元数据会让 Agent 误判它已经可用。

## 当前结论

- 状态：`incubating`，不可安装、不可调用。
- 当前目录只保存设计边界，不承诺命令、依赖或输出格式。
- 业务报告、调试输入、渲染预览和生成结果必须留在本地，不能提交到 Git。

## 定型时的选择

满足以下条件时放到仓库根 `skills/<skill-name>/`，作为全局 Skill：

- 工作流可脱离某个具体工程运行；
- 所需脚本、模板和规则可在 Skill 目录内自包含；
- 安装后只需 Skill 自身依赖，不依赖业务数据库或工程状态。

满足以下任一条件时保留为 `projects/report-generation/.codex/skills/<skill-name>/`：

- 强依赖本工程的模板、数据源、配置或审批状态；
- 输入输出需要固定的工程目录约定；
- 脚本与报告项目代码必须同步演进。

## 发布前必须明确

1. 给出三条以上真实触发示例和不应触发的反例。
2. 明确输入格式、输出文件、模板来源、隐私边界和失败行为。
3. 选择全局或工程本地交付形态，只保留一个权威实现。
4. 创建符合规范的 `SKILL.md`、必要的 `scripts/`、`references/`、`assets/` 和 `agents/openai.yaml`。
5. 补齐依赖锁定、自动测试、Skill 校验和本目录 ignore 规则后，再把根 README 状态改为“可用”。
