# 业务规则与数据结构

## 数据权威

- 用户在每次申请开始时明确确认的总表是当次权威数据源，正式物料只来自该工作簿的第一个工作表。
- 工程根目录的 `material_codes.db` 是用于检索和预分配的 SQLite 镜像。
- 新生成的编码是预定值；写回权威 Excel 并重新同步后才正式生效。
- `sync` 是全量重建。必须由用户明确同意，并在失败时恢复旧库。
- 每份新申请开始前，无论现有 SQLite 的同步时间或数据状态如何，都必须让用户明确选择：提供
  新权威总表重新同步，或沿用当前数据库。不得默认沿用。
- 用户明确选择沿用后，以 `use-existing --confirmed` 记录一次性确认；用户明确选择新总表后，
  成功的 `sync --confirmed` 记录一次性确认。`prepare` 必须验证数据库指纹、消费确认，并拒绝
  缺失、已消费或已失效的确认。
- 新的同步尝试会先作废此前的数据库选择；若同步失败并恢复旧库，也不得恢复旧选择，必须重新
  询问用户。
- 第一页只有“新物料编码 J”非空的行进入正式 SQL。
- 产品名称非空且 A-K 全空的行才是本次待申请行；后续用户会将这些行单独复制成带表头的
  `申请.xlsx` 再进入交互流程。
- J 为空但 A-K 已有分类、旧编码或采购部门等内容的行，不算本次待申请；将其单独报告为“异常缺码”，
  同样不导入 SQL。
- 只允许读取工作簿顺序中的第一个工作表。第二页及后续工作表不读取数据、不导入
  SQL，也不参与新编码流水号计算。
- 申请交互不得把预定编码插入 `material_codes.db`。正式 SQL 只能由总表同步脚本重建。
- 总表较大；人工/模型只检查表头和少量抽样行，完整导入使用流式 Python XML 解析。

## 编码结构

`J = C + E + G + 流水号`，总长 10 位：

- C：大类编码，2 位。
- E：一级子类编码，2 位。
- G：二级子类编码，2 位。
- 流水号：4 位，范围 `0001`–`9999`。
- H：`C+E+G`，共 6 位。

为一个 C/E/G 前缀分配新编码时，只取第一个工作表已同步记录中的现有最大流水号再加一。
同一前缀的多条新申请必须连续分配，不得重复。

## Excel 字段

权威总表主工作表的关键列：

| 列 | 含义 |
|---|---|
| A | 引用（大类+一类+二级） |
| B/C | 大类 / 大类编码 |
| D/E | 一级分类 / 一级子类编码 |
| F/G | 二级分类 / 二级子类编码 |
| H | 上级分类（C+E+G） |
| I/J | 旧物料编号 / 新物料编码 |
| K | 采购部门 |
| M/N/O | 产品名称 / 产品规格 / 单位 |
| S/T | 用途 / 编号申请人 |

同步脚本按表头文字定位字段，允许列顺序变化。结构校验错误是阻断项；历史重复编码或空名称
若只作为警告报告，不自动修改源数据。

## 候选与授权

- 先按去首尾空格后的“产品名称 + 产品规格”做严格相等检查，只检查在用物料。
- 若严格匹配只对应一个不同编码，直接复用其原编码和分类写入结果 Excel，不生成新编码，
  也不向 SQLite 插入新行。结果 Excel 中该条复用记录整行以浅红底、深红字标记，便于人工核对。
- 复用时单位严格使用本次申请表的值；申请单位为空则结果单位也为空，不沿用原物料单位。
- 若严格匹配对应多个不同在用编码，把全部精确匹配编码优先列入候选并转人工确认；用户选中
  哪个就直接复用哪个，仍不得生成新编码。不得自动选择最低、最高或最早编码。
- 默认按“产品名称 + 用途”检索 Top5；相似度只用于排序，不等于分类正确。
- 默认逐项向用户展示候选，并按明确候选序号提交。
- `0` 表示结果保留申请信息，但分类和新编码留空，也不写数据库。
- “生成全部编码”不是分类选择；“剩余全部用 Top1”才构成批量 Top1 授权。
- 阈值自动选择必须由用户主动要求并指定阈值。

## 安全不变量

- 所有安全不变量均为脚本硬门禁；不得只写在提示词或文档中。
- 底层 `process_application.py`、`sync_db.py`、`search_material.py`、`export_excel.py` 禁止直接执行，
  必须由 `workflow.py` 注入内部调用上下文。
- 候选固定 Top5 且固定排除停用物料，不提供放宽参数。
- `prepare` 的前置数据库来源确认是刚性门禁：每份新申请仅能消费一次，不得跨申请复用。
- `prepare` 和 `show` 不得修改数据库；`prepare` 可以为唯一精确匹配写入本 job 结果 Excel。
- `commit`、`top1`、`auto`、`sync` 必须经 Codex 工作流入口执行；前三者只能写独立结果，
  只有 `sync` 可以修改正式 SQL。
- 每份申请使用独立 job 目录、独立候选缓存和独立结果表。
- 同步成功后所有旧候选都视为失效。
- 每次生成需展示：类别 C/E/G、同步库中的原最大编码、新编码和流水号组合。
- skill 中不得存在直接向 `materials` 插入预定编码的业务入口；正式 SQL 只能由总表同步重建。
