# NAS Hub：同步、首次使用与恢复

NAS 是共享的交换 Hub；每位 HR 平时在自己的本地工作副本上工作。不要让多人同时直接编辑同一个 NAS 业务目录，也不要把 NAS 当成普通“自动同步盘”。完整备份和 NAS 快照应由管理员另行维护。

这里的 NAS 路径必须是目标环境实际可访问的共享目录（通常为 UNC 路径）。本工程当前没有对公司 NAS 做实机验收；安装 Agent 必须在目标网络中先做可读、可写和断网恢复验证。

## 三种开始方式

### 第一次使用，Hub 还不存在

安装 Agent 先确认共享目录可写，再明确执行一次 `sync` 并传 `initialize_remote:true`。这一步只由管理员/安装 Agent 做，避免把错误目录初始化成正式 Hub。

### 新电脑接入已有 Hub

建立一个**空的本地工作副本**，先从已有 Hub clone，再由 Agent 验证记录和原件哈希。不能把一个已有业务目录和 Hub 直接拼接。

### 暂时断网

继续在本地工作；看板可以浏览，WorkBuddy 可以录入、审核、登记面试和回写台账。恢复网络后执行同步。未同步不代表本地工作丢失。

## 每日流程

1. WorkBuddy 在本地完成新增或修改。
2. 浏览器看板查看总览和审核证据。
3. 有网时点击“一键同步”，或让 WorkBuddy 执行同步。
4. 确认同步状态；看到冲突就停下，不删文件、不重新导入。

同步传输当前索引引用的记录、简历原件、人工转录和二面附件，并在各侧生成本次索引历史；不会复制所有旧版本历史或 `ledgers/*.xlsx` 等导出临时文件。Excel 改完后先让 WorkBuddy 回写记录，再同步记录。导出的 Excel 如需留档，应另外保存到公司的台账归档目录。

看板的“已同步”表示本机没有上次同步以来的新改动；它不持续查询 NAS。开始工作前再点一次同步，才能拉取同事最近的进展。

## 冲突怎么处理

不同记录的修改可以合并。同一条记录在本机和 Hub 都改过时，系统保留本机和 Hub 两个版本并报告冲突，不自动覆盖。HR 只需说：**“请列出双方版本和差异，我选择保留本机/共享空间版本。”** Agent 得到明确选择后，使用 `sync-resolve` 并核对双方哈希；不得用普通招聘进度修改来绕过冲突。

## 恢复和安全

同步失败时保留本地目录、`.sync` 状态和冲突报告，先离线继续工作。需要换目录时复制到新的空目录，先运行 `doctor` 和同步状态检查，再恢复；不要删除锁、历史、原件或 Hub 文件。锁不会自动过期或强拆；确认没有写入者后由管理员处理。

若 Hub 暂时不可用，记录本地最后同步时间，恢复后再同步。若发现原件哈希不一致或版本异常，停止写入并让 Agent/管理员检查，不要手工改 JSON。
